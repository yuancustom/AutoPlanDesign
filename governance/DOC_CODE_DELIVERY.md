# P1 / P2 / P3 文档与代码双交付计划

版本：0.3.0｜2026-09-11｜本轮范围：三项目交付管控 + P1可操作原型

## 1. 决定

三个项目都必须有可维护文档、可执行代码、测试证据和使用说明。文档写完不等于功能完成，目录和CLI骨架也不等于产品完成。本轮不重新清空仓库、不修改冻结baseline、不覆盖P2/P3已有文件和未解决阻塞。继续只维护main，不创建分支或PR，不强推。

产品实现总任务继续以 `backlog.json` 为准；本轮补充 `delivery_status.json` 分开记录文档、原型、生产代码、真实模型、用户验收五个维度。旧任务不因原型能点击而自动DONE；该补充清单不能替代总台账。

## 2. 三项目必须交哪些东西

| 项目 | 文档入口 | 代码落实位置 / 下一步 | 验收重点 |
|---|---|---|---|
| P1 | 既有 P1_DEVELOPMENT_SPEC / MODELS_PREPARATION + 新 UX_PROTOTYPE_GUIDE | prototype/ 已有浏览器原型；正式 src/autoplan_outline/ 与 frontend/ 分层实施 | 绘图/尺度/数量/同源实验/原始图复核 |
| P2 | projects/region-edit/docs/DOC_CODE_PLAN.md，后续补 API/数据表/恢复与区域编辑算法设计 | frontend/ + src/autoplan_region/；先mask映射与不可变编辑记录，再模型 | 选区外保护、前后/过程/拒绝/回滚、几何过期阻断 |
| P3 | projects/plan-delivery/docs/DOC_CODE_PLAN.md + 原vendor Skill | frontend/ + src/autoplan_delivery/；先输入适配/参数证据，再建模与同源导出 | 二维三维网页查看、单位/洞口/层间关系、三格式回读 |

frontend/ 是正式代码目标目录，不因写在表中就表示已存在。P1本次原型是单文件 HTML/CSS/JS，便于无需依赖就试用；正式产品仍按此前React+TypeScript方案实现，不把原型中的示例流程复制成真实任务运行器。

每项目文档最小集合：需求与非目标、UX与错误状态、数据和API、算法与模型角色、测试矩阵、部署、每次变更/交接。代码最小集合：独立可安装包、明确输入输出的公共接口、独立测试、接口契约测试、真实运行入口、错误与持久化；返回空文件或固定示意不得当成功。

## 3. 一项功能的完成标准

需求→界面/接口设计→实现→单元/集成测试→实际环境验证→用户验收。每阶段保留不同状态，不用一个“完成”混在一起。

文档验收：输入/输出/失败情况明确，能映射任务ID和测试；代码验收：新环境可运行，失败路径也测；模型验收：真实权重/后端/输入hash/原始输出/耗时和资源有证据；用户验收：针对具体版本的显式反馈，不可由Agent代填。

模型未执行统一NOT_RUN；原型进度是交互示意。所有评分保持空值，模型目录中的推荐是候选，不表示适配已完成。

## 4. 推荐分段开发，不做“只写文档”的项目

### 第一段：不加载模型也能完成真实操作
P1：SVG编辑/受限导入→尺度确认→工程轮廓导出→参数数量校验。新原型用于校准这段交互；真实API、版本存储和跨层轮廓还要独立开发。
P2：原图→画笔→原分辨率mask→保存before/request/mask→确定性编辑回放。模型不参与，验证高DPI、缩放、撤销及持久化。
P3：给定匹配几何fixture与明确尺寸/层高→输入适配→共享BuildingIR→最小同源文件→网页回读。fixture必须标合成，不能称完成识图。

### 第二段：分别接入真实本地模型
P1规划/图面分开适配；P2局部编辑与几何同步；P3视觉识别与构件几何提案。模型不执行任意生成代码；结构化提案经白名单工具和几何检查后生成候选。

### 第三段：每项目比较多模型，再组合Agent
冻结同一输入/参数/预算。分别比较规划、图面、区域编辑和识图。稳定ID/版本/hash贯穿P1→P2→P3。Agent负责路由、状态、暂停、审批、幂等和恢复，不重新实现建筑算法。

每段采取小提交，文档/API/测试随代码同步变化。发现合同冲突先ADR，不静默改变共享单位或审批含义。执行预算/硬件分组与模型数量沿用benchmarks/PROTOCOL。

## 5. 本轮 P1 原型是什么

五页均可切换，包含实际 SVG简化解析、顶点拖动、折线绘制、缩放平移、撤销重做、总宽等比校准、轮廓SVG/PNG导出、分层数量校验、机柜余数分配、模型配置选择、SHA-256体验快照、示例步骤和体验记录导出。

没有正式HTTP接口、通用排房求解器、模型推理、真实成绩、批准事件或P2/P3写入。结果页的三层图是固定合成示意，不会跟随输入重排，页面显式说明。收藏按钮只是本地偏好。浏览器草稿保存属于便利功能，不是审计存储；不可用时提示导出留存。

## 6. 开发与运行的安全边界

用户使用Mac mini 16GB作为第一实测环境；模型串行，本地优先。权重/字体/凭据不进仓库。浏览器原型不调用网络服务，不下载模型。其简化SVG白名单不是通用SVG产品解析器；正式后端另做大小、解析时长、资源引用、路径授权等防护。

P3网页展示优先评估用户有会员的BIMFACE，但会员不能自动证明所有格式与API授权。现有支持格式清单可核对DXF，未能据此确认GLB原生转换；需要单独技术验证，不能把“任意GLB上传即能显示”写成保证。AppSecret留服务端，不放前端。采用云转换要单独确认文件外发；本地推理不意味着BIMFACE云展示也是本地。[S1][S2]

为保持三格式合同，网页是应用能力而非第四份建筑成果。必要中间文件只在受控工作区，交付目录仍仅DXF/PDF/GLB；原始vendor保持不动。

本轮可评审：双交付计划、P1交互原型代码及测试、P2/P3文档到代码任务映射。生产功能未完成，模型未运行，用户易用性尚待亲自体验。旧47项几何测试、当前原型测试、未来模型质量不能合并成一个“系统成功率”。
