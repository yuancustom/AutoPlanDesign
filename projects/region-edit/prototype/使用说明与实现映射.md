# AutoPlanDesign · P2 区域重绘交互原型

版本：v1.0｜用途：产品交互评审｜范围：单张已有平面图 → 涂抹 → 候选 → 接受/拒绝 → 版本恢复

## 打开方式

打开 `P2_区域重绘交互原型.html`。页面内已包含本次用户提供的平面图、样式、图标与 JavaScript，不依赖 CDN，不需要安装模型或启动后端，也不会上传图像。

浏览器需支持现代 Canvas、Pointer Events 与 JavaScript。建议在桌面浏览器中评审。下载后用浏览器打开完整 HTML；聊天内预览可能限制脚本、存储或下载能力。

页面优先使用 IndexedDB 在本浏览器中暂存会话。浏览器不允许时，顶部显示“临时会话”提醒，仍可操作和导出工程。浏览器清理数据、更换浏览器、文件位置或来源变化都可能导致自动保存数据不可见，重要结果请始终用“保存工程”导出 JSON。

**图像候选是程序绘制的演示，不调用 AI，不根据任意文字自动设计。** 右栏的“演示候选效果”决定演示内容，提示词原话用于展示记录。所有版本均保持 `IMAGE_ONLY` 和尺度未知，没有 P3 交付能力。

## 五个页面

| 页面 | 重点操作 | 看什么 |
|---|---|---|
| 编辑工作台 | 画笔、橡皮、保护笔、矩形、平移、缩放、撤销/重做、提示词 | 同时看见允许修改区、重叠保护区与只读上下文 |
| 候选对比 | 滑杆、并排、差异、回贴前演示图、接受、拒绝、再试一个 | 区外和保护区检查，候选是否基于当前版本 |
| 版本历史 | 选中任意历史、与当前比较、恢复、撤回上一次版本修改 | 当前版本与来源关系；恢复不删历史 |
| 过程记录 | 按事件筛选、展开参数、导出过程摘要 | 原话、笔画、权限、候选、接受/拒绝、恢复 |
| 操作与实现 | 三种交互场景和前后端职责表 | 哪些已在原型运行，哪些正式开发需要接入 |

## 第一条体验路线：完成一次修改

1. 进入“编辑工作台”，点击右侧 **机柜排布**。系统载入手工示例选区和描述，选中原图下排中左的机柜区。也可以自行涂抹和修改描述。
2. 点击 **预览修改范围**。绿色是允许改写的范围，橙色表示涂抹中被保护的部分；蓝框只提供参考上下文。修改描述和来源版本同时冻结。
3. 勾选了解演示方式后，点击 **确认范围，生成演示候选**。原型按本页程序绘制候选，显示处理阶段；可以取消。
4. 在“候选对比”拖动中线，或切换并排/差异。当前仍为 r0。
5. 点击 **接受，保存为 r1**。这时才新增版本。点击拒绝则不改变当前版本，候选和理由仍保留。

## 第二条体验路线：撤销与恢复

| 想解决的问题 | 应点击什么 | 数据怎么变化 |
|---|---|---|
| 刚才画错一笔 | 工具栏撤销，或 Ctrl/⌘ Z | 笔画从草稿 commands 移入 redo；正式版本不变 |
| 撤销后想恢复笔画 | 工具栏重做，或 Ctrl/⌘ Shift Z | 从 redo 恢复笔画，重新栅格化蒙版 |
| 生成候选不满意 | 候选页“拒绝候选” | 记录拒绝理由，保留候选，head 不变 |
| 已接受的最近修改不想要 | 版本页“撤回上一次版本修改” | 复制当前父版本的内容，追加恢复版本 |
| 想恢复很早之前的方案 | 点击历史 r0，再“恢复此版本” | 创建新版本，parent=current，restore_from=r0 |

例如：已有 `r0 → r1 → r2`，恢复 r0 后变为 `r0 → r1 → r2 → r3`。r3 的图片内容来自 r0，但 r3 的父版本仍为 r2。中间的修改和过程没有消失。

草稿撤销和业务版本恢复是两个独立机制。“重置演示会话”则是另一个明确确认的动作，会替换当前浏览器会话，使用前应导出工程。

## 第三条体验路线：过期候选不覆盖最新版本

先基于 r1 生成候选但暂不接受，再去版本历史恢复 r0，得到新的 r2。回到候选页，可以看到“来源冲突”提示，接受按钮被禁用。

这是**同一页面内的来源版本检查演示**，不是跨标签数据库事务或多人协同。正式产品应通过数据库事务比较 `expected_head_revision_id` 与当前 head；冲突返回 409，候选保留而不是自动合并。

## 已实现的前端逻辑

### 画布和蒙版

浏览器鼠标位置先减去 Canvas 在页面中的位置，再减平移、除以缩放，得到原图像素坐标。笔宽保存为原图像素；设备像素比只影响 Canvas backing store。

草稿保存原图坐标下的命令，不保存屏幕截图。画笔和矩形操作作用于编辑蒙版，保护笔作用于手工保护蒙版。撤销/重做通过命令栈重放实现。橡皮只擦对应蒙版，不擦原图。

内置图片的墙门、楼梯、走廊和房名保护来自人工坐标预设，**不是自动识别模型**。导入其他图片后，这些预设关闭，需要自行画保护区。

### 权限与最终合成

本页计算 E（原始涂抹）、P（保护）、A（有效授权）及 C（只读上下文）。A 取编辑区扣除保护区；内置样例也排除建筑外部。候选先生成在独立 Canvas 上，再按 A 写回，最后保留 P 和 A 外的原像素。

区外是否不变，是把 before 与 final 解码像素逐一比较得到的，不是固定写一个“通过”。回贴前演示图和最终候选分别留存。后者为零变化不意味着前者没有修改保护内容，也不代表真实模型表现。

### 版本与数据

- `draft`：未提交笔画与提示词，可撤销。
- `attempts`：每次演示请求和候选，包含 base、mask、原话、状态、raw/final、差异和检查。
- `revisions`：初始图、接受版本、恢复版本，保留 parent 与 restoreFrom。
- `events`：追加事件，记录请求、就绪、接受、拒绝、取消、恢复等公开过程。

工程导出包含图像，因此应作为私有数据保存。过程摘要不含完整图像，但可能包含用户提示词和操作信息，同样不要直接提交公共仓库。

## 正式产品如何实现

| 模块 | 原型实现 | 正式 P2 接入建议 |
|---|---|---|
| 画布 | 原生 Canvas，独立 HTML | React + TypeScript + Konva 组件化；保留相同原图坐标约定 |
| 生成 | 三种明确的程序演示 | 本机 FastAPI 执行任务；专用 masked ComfyUI adapter |
| 历史 | 内存对象 + 可用时 IndexedDB | SQLite 事务 + 内容寻址文件目录；图像不可变 |
| 接受 | 同页比较 base 与当前 head | 原子 CAS、幂等 key、权限与审批绑定 |
| 回滚 | 追加恢复版本 | 同样追加 revision，并使不匹配的几何和导出失效 |
| 崩溃恢复 | 重新打开时结束未完成的演示任务；可导入工程 | outbox、lease、外部 prompt ID、SUBMISSION_UNKNOWN，不盲目重试 |
| 几何 | 无几何，固定 IMAGE_ONLY | 几何补丁/验证；不匹配时 STALE，阻止 P3 |
| 过程 | 可见输入、参数、像素指标、决定 | 追加事件与文件哈希，不存储模型隐藏思维链 |

后端接口按已形成的 P2 设计分为：会话导入、权限预览、任务提交、任务事件、候选接受/拒绝、版本恢复、过程读取。这里没有假装这些接口已经部署。

## 交互与快捷键

B 画笔；E 橡皮；P 保护笔；R 矩形；H 平移；空格+拖动平移；滚轮围绕鼠标缩放；`[` / `]` 调笔宽。快捷键不抢占提示词输入；Esc 关闭弹窗。弹窗提供键盘焦点循环。

## 测试与限制

浏览器回归结果见 `交互测试报告.json`。本轮使用 Chromium 内联加载 HTML 验证，不依赖远程网页或模型。

测试环境禁止直接导航到 file/localhost，因此未通过关闭浏览器安全机制来绕开限制；改为在允许的页面内呈现自有 HTML。该加载方式没有可用的持久存储来源，已检查明确降级提示及工程 JSON 导出/导入；IndexedDB 在用户浏览器的跨会话保存需要实机确认。

没有测试真实模型、Safari、实际多标签并发、真实建筑几何、尺度或工程规范。手机尺寸主要验证排版，绘图交互优先使用电脑鼠标。

## 隐私与仓库

交付 HTML 内嵌本次用户平面图，仅作为本地对话附件，不自动同步到公共 GitHub。要形成公开仓库原型，应替换成明确授权或合成的测试图片；交互代码本身可以再提取为 P2 前端开发起点。
