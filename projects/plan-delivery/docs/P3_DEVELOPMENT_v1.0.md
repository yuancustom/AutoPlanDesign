## 01｜产品定义与关键决策

### 1.1 目标和成功标准

用户提供一栋建筑的一张或多张详细平面图，系统识别楼层、墙体、门窗、房间、楼梯、洞口和必要设施；补齐绝对尺度、层高等不能可靠从平面图获得的信息；生成可追溯的统一建筑几何，再产生可编辑 DXF、矢量 PDF、自包含 GLB。用户在同一网页审阅输入图、二维成果与三维模型，并比较不同大模型执行同一 Skill 的结果。

“一张看起来像三维的效果图”“外轮廓挤出盒子”“把原图贴在楼板上”均不满足本项目定义。图片输入再详细，也不能自动证明楼板厚度、门窗高度、设备荷载、消防和结构已知。输出默认是方案级几何重建，不升级为施工图或完整参数化 BIM。[U01]

### 1.2 与 P1、P2 的边界

| 项目 | 职责 | P3 的处理原则 |
|---|---|---|
| P1 | 从带尺寸外轮廓生成初步布局 | 可提供可选几何侧车；不成为 P3 的必经步骤 |
| P2 | 对平面图指定区域修改并保存历史 | 提供确认后的图片版本；旧几何失效则进入重新识图流程 |
| P3 | 忠实识读详细平面图，重建及展示成果 | 不私自移动楼梯、修正房间布局、统一各层轮廓 |
| 总 Agent | 路由、审批、任务和资源编排 | 使用 P3 公开接口，不绕过其输入校验与用户确认 |

**对旧总控的澄清：** `geometry_status=STALE` 不能被当作可信几何直接导出，但不应一概拒绝用户的最新详细图片。系统应忽略旧几何，创建新的 `IMAGE_ONLY` 重建任务，经识图、尺度与人工复核产生新几何，再允许输出。该语义需要以合同变更记录更新 CONTROL/PlanRevision，不能在实现中悄悄改变。[R02]

### 1.3 本文确定的设计方向

| 决策 | 采用方式 |
|---|---|
| 主输入 | IMAGE_ONLY：详细平面图图片及必要补充参数；JSON/CAD 作为增强输入 |
| 几何真源 | BuildingIR，而不是模型截图、BIMFACE 云端文件或导出的 GLB |
| Skill | 保留用户 V1.0.0 原包及哈希；适配代码放 vendor 外 |
| 网页展示 | BIMFACE 优先，二维 DXF 与三维 GLB 外部构件先做能力验证 |
| 三维语义增强 | GLB 外部构件不满足构件级功能时，使用内部 IFC 派生路线；须通过策略与权限确认 |
| PDF 阅读 | PDF.js 独立展示实际交付 PDF，不能仅用 CAD 窗口替代 PDF 验收 |
| 模型测试 | 固定 Skill、工具、输入与预算，分别评测识图、受控 Agent 和端到端结果 |
| 本地优先 | Mac mini 16GB 首测；模型串行，本地几何生成；BIMFACE 是单独获准的外部展示服务 |

## 03｜输入、产物与新网页需求

### 3.1 三类输入通道

| 通道 | 内容 | 处理 |
|---|---|---|
| IMAGE_ONLY，首要验收路径 | PNG/JPEG/TIFF 等单层图、合并图板；可选扫描 PDF | 识别/人工切分楼层、校尺、补层高、配准和重建 |
| IMAGE_WITH_GEOMETRY | 图片、匹配哈希的 PlanRevision/BuildingIR/尺度 | 先检验版本与图几何一致；通过后复用，不重复猜图 |
| CAD_ASSISTED，后续增强 | DXF、矢量 PDF 加图片或说明 | 原生几何优先，仍检查单位、覆盖尺寸和版本冲突 |

首期必须支持“上传已设计好的三层图板，分别框选三层”与“上传三张独立图片，手动指定楼层”。支持一层建筑；屋顶平面不是默认第四层；没有证据不能把不同方案误合成不同楼层。

### 3.2 下载成果合同保持不变

```text
deliverables/<approved_revision>/
  <project>_<revision>_plans_mm.dxf
  <project>_<revision>_drawings.pdf
  <project>_<revision>_model_m.glb
```

只有这三份建筑成果。默认 DXF 多层合图、PDF 多页、GLB 完整装配。说明、假设、改动与未检查项目进入 PDF；必要元数据进入 DXF/GLB。开发文档、日志和测试数据不是建筑成果。[U01]

### 3.3 网页和中间文件不与旧约束冲突

旧 Skill 的“不交 HTML 查看器”指不在建筑交付目录附送独立 HTML 文件；本次新增的是**部署在系统内的网页应用**。本项目不因此多交一份 HTML 或 IFC。内部 `_work/` 可以保存渲染截图、JSON、逐层预览 DXF、可选 IFC；它们被标为 `internal_derivative`，不会混入下载成果。

新增 ADR-P3-001 应明确：允许网页版审阅；外部发布是独立状态；IFC 若启用，只为 BIMFACE 语义展示而内部派生，并保留与最终 BuildingIR/GLB 的一致性校验。原 Skill 输出格式校验器不被放宽。

前端建议 React + TypeScript；图片校准用 Canvas/SVG 叠层；BIMFACE 封装成适配组件；PDF.js 阅读最终 PDF。这里是项目技术选型建议，不要求重做 P1/P2 的 UI，也不把 Canvas 展示误称为真实矢量 CAD。[B10]

### 4.3 识别结果复核，而不是重新设计

点选墙、门窗或楼梯后，右侧展示 ID、对应原图框、识别类型、几何尺寸、尺寸来源、冲突及模型版本。用户可纠正“把窗认成门”“墙端吸附错了”等重建错误；系统新增候选版本并重跑校验。

改变原设计的操作，例如移动楼梯、添加走道、改房间用途，需要明确 `design_change` 审批，并记录前后差异；不能混入“识别修正”而绕过 P2/变更流程。只读二维三维查看器不应暗中直接修改 BuildingIR。

### 4.4 模型对比界面

默认同时激活两个可交互视口，其他候选先显示同相机静态预览，减少 16GB 机器的浏览器压力。所有候选锁定建筑世界坐标、楼层、相机、剖切面、可见类别和显示模式。切换候选不自动重新缩放到最合适的包围盒，避免用画面大小掩盖模型尺度错误。

显示原始识别结果、工具修复结果和人工修正结果三档，不仅展示最终最漂亮的版本。盲评隐藏模型名，以 A/B/C 编码展示，评审后解盲。

## 05｜总体架构与职责

```text
Web UI
  → P3 API / 权限 / 版本与审批 / 持久任务队列
      → SkillRunner + 固定工具契约
          → 本地 VLM Adapter：识读/候选/公开解释
          → 几何工具：校尺、墙门窗、楼层连接、BuildingIR
          → 同源导出：DXF / PDF / GLB
          → 回读与评测工具
      → ViewerPublisher
          → BIMFACE 二维转换与三维展示
          → PDF.js / 本地 GLB 回读核验视口
  ← SSE进度 / 问题与结果 / 浏览器短期凭证
```

模型不直接持有 BIMFACE Secret，不直接写交付目录，不自动改审批。几何服务不依赖 BIMFACE 才能运行；BIMFACE 失败时本地成果仍保留，但 `WEB_READY` 不得标记成功。

建议后端 FastAPI + Pydantic，几何在独立 worker 进程运行；单机开发使用 SQLite WAL 和持久化 jobs/events 表，服务化扩容再切 PostgreSQL 和任务队列。长任务不能只放 Web 进程的内存 BackgroundTask。文件用内容 hash 定位；数据库保存版本、索引和关联，不保存明文密钥。

网页应用和本地 worker 可同机运行。需要局域网访问时，使用获准的 HTTPS 入口和认证；不得为了 BIMFACE 回调把 Mac 任意服务暴露到公网。

## 06｜参数、证据与尺度校准

### 6.1 参数采集规则

| 参数 | 已知时 | 缺失时 |
|---|---|---|
| 楼层和图纸对应 | 读取标题/标高并让用户快速复核 | 给出待分配列表，不猜顺序 |
| 长度与单位 | 从可信尺寸、原始单位、两点校尺取得 | 无可靠尺度时停在无尺度分析，不输出伪米制成果 |
| 层高与含义 | 每层记录 floor-to-floor；顶层到屋面单独说明 | 净高不直接当层高；请求参数或草模假设授权 |
| 跨层定位 | 轴网、稳定外墙角点、竖井等约束 | 证据不足时要求定位点，不强行对齐到同一包围盒 |
| 墙厚、楼板厚度 | 图纸事实或经授权的方案参数 | 不用绘图线宽证明墙厚；未知先标记 |
| 门高、窗台/窗顶 | 门窗表、剖面或明确输入 | 可作为草模假设但必须单独披露 |
| 设备、栏杆、屋面 | 已知轮廓及高度才建细节 | 简化占位或不建；不补结构/设备选型事实 |

每项使用原 Skill 的七种 `status`：user_confirmed、drawing_explicit、derived、estimated、assumed、unknown、conflict；批准状态单独使用 confirmed、accepted_for_draft、pending、not_applicable。模型的高 confidence 不能替代用户批准。[U01]

### 6.2 校准方法

单层无透视、无非等比拉伸时，用相似变换：`world_xy = translation + scale × rotation × [u, -v]`。一条可信长度可以提供尺度，但不自动提供跨层平移、旋转或北向；这些仍需定位约束。第二条不同方向长度用作核验，不把两个尺寸矛盾强行压成非等比图。

每层保存原始文件坐标、裁切、旋转/去畸变、像素到建筑坐标的全部可逆变换。显示设备像素比、缩放和平移只影响界面。扫描 DPI 或“1:200”文字在截图缩放后不能独立证明真实尺度，优先实际图上尺寸线/图示标尺。

仿射校准至少需要三个不共线的可靠对应点，平面透视校正至少四个非退化对应点；适用前提和残差必须记录。这些是数学上的约束数，不是足以保证源图真实无误的证明。任何可能改变原设计几何的校正先出差异图，等待确认。

沿用原 Skill 建议的 2% 各向尺度差仅作识别异常告警的初始配置，不是设计或测量精度标准。清晰但由生图模型生成的比例尺也可能只是装饰，不能因“画了刻度”直接信任。[U01]

### 6.3 推导依赖和精度

楼面标高由已确认的基准及相邻层高累计；顶层屋面参考面不等于建筑最高点。面积来自重建多边形，误差继承其来源。每次参数变化建立依赖失效列表，重生成所有受影响楼层、三份成果和网页缓存。

严格分开源图重建不确定度、建模假设和数值运算容差。毫米级回读一致，只说明同源文件互相一致，不说明真实建筑从图片恢复到毫米级。

## 07｜识图与几何重建算法

### 7.1 分阶段识读，不一次生成整栋巨大 JSON

先识别页面与楼层，再识别外轮廓/内院及主要墙，再识别门窗/楼梯，最后房间文字与机柜等设施。对低置信度局部裁切放大。优先 VLM 直接读图，只有实际无法读清的文字再启用局部 OCR 辅助并复核，不把 OCR 文本直接变成几何事实。

预处理只做可逆旋转、对比度辅助视图和安全裁切，原图永不覆盖。图像增强不得移动线、消除门洞或“美化”尺寸；需要的降噪视图与原图同时保留，模型评测也记录该变体。

### 7.2 VLM 与几何工具的分工

VLM 输出候选构件类别、原图区域、关联 ID、疑点和公开的依据摘要；不要求一次给出全楼精确毫米坐标。CV/几何工具提供线段、弧线、连通域和可吸附候选，VLM 决定语义，工具再拟合和校验。若用专用分割/检测网络，须作为独立实验变量，不能只给某一个大模型额外帮助。

大图采用有重叠的分块识别，保存 tile_to_source 变换；跨块墙体通过几何重叠、方向和语义去重。禁止按名字去重两个不同“办公室”，也不能把相邻门合并成一扇大门。初始块大小和预算进入实验配置并预先冻结。

### 7.3 墙与房间

墙保存中心线加厚度，或平面实体多边形；明确外轮廓按外墙外皮还是轴线定义。墙厚向内/两侧扩张依据约定，不让给定外包尺寸被额外墙厚扩大。正交与斜墙先支持；弧墙用参数曲线或有误差上限的离散表达，不支持的构件明确报告。

节点吸附只在预设容差、相同平面和相容语义下进行，每次修复记录前后几何。封闭房间边界与房名标签分开存储；只有名称点时不能伪造房间面积。多翼楼、内院、竖井均用外环/孔洞或多多边形，不能用连接线穿越空地。

### 7.4 门窗真实开洞

门窗必须指向宿主墙，保存沿墙区间、底高、顶高、宽度、开启方向和证据。检查洞口是否超过墙端/墙顶、是否重叠、方向是否对。先形成真正墙洞，再放置门扇或窗框；不使用透明矩形替代墙洞。

首期正交墙采用沿洞口起止及高度切片的确定性实体生成，减少三维布尔不稳定；复杂斜墙/弧墙使用经过测试的几何内核，失败时保留问题，不回退成封闭墙。门扇开启弧只在二维表达，不成为三维承重实体。

### 7.5 楼层、楼板和楼梯

统一使用建筑 Z 向上；每层楼板顶/底标高明确。楼板必须减去中庭、竖井和楼梯实际开洞。楼梯保存 from_floor、to_floor、平台、梯跑、起终标高、踢面数和踏面计数约定；相邻楼层层高不同就重算。

用 `sum(risers_i × riser_height_i) = target_z - start_z` 校核实际累计高差；同时检查终点平台是否落到目标楼层、井道及板洞是否避开人体通行空间。算法能计算几何净空，不等于已经有适用工程规范阈值。缺少阈值则标 NOT_RUN/待专业检查。

原图楼梯错位必须报冲突。未经授权不得移动楼梯。用户允许暂定草模时可输出明确标为 PROVISIONAL 的模型，但不能同时标“楼层连接通过”。顶层没有上屋面楼梯证据，就不生成上行梯段。[U01]

### 7.6 设施与重建质量

按原图位置识别机柜、设备、办公桌、洁具等；模型使用简化占位体并记录 `representation=proxy`。可见数量不能读准时给候选数量和证据，不按房间面积随意填满。未知设备高度和检修距离要补充或取得草模授权。

网格质量检查有限坐标、退化面、法向、洞口、重叠和构件变换；不能要求整个建筑所有玻璃/面片都合成单一封闭实体。为性能合并网格时仍保留对象/子网格映射，不牺牲跨格式可追溯性。

## 08｜数据合同：项目事实与 BuildingIR 分离

### 8.1 主要实体

| 实体 | 最小内容 |
|---|---|
| SourceAsset / FloorSource | 文件 hash、页码、裁切、楼层和各步坐标变换 |
| ProjectFacts | 原 Skill project.json：数值、单位、证据、依赖、批准、策略 |
| BuildingIR | 楼层、轮廓、墙、门窗、楼板、楼梯、房间和设施 |
| ReconstructionRun | 输入快照、Skill/工具/模型版本、预算、事件、结果与错误 |
| DeliverableRevision | IR hash、三种文件 hash、导出参数、回读及批准 |
| ViewerPublication | BIMFACE 文件/模型 ID、通道、映射、权限、状态、关联版本 |
| BenchmarkTrial | 案例、模型与量化、原始候选、修复、性能、分数和人工介入 |

`project.schema.json` 当前对很多对象设置 additionalProperties=false，所以 BIMFACE ID、实验字段不能直接塞进旧 `project.json`。新字段置于 P3Request/运行数据库；兼容适配器只投影原 Skill 接受的字段。另建 BuildingIR Schema，不把原参数 Schema 冒充完整建筑模型 Schema。[U01]

### 8.2 请求示例：缺信息时合法接收、阻断建模

```json
{
  "schema_version": "p3.request/1.0",
  "project_id": "P3-PILOT-01",
  "input_mode": "IMAGE_ONLY",
  "source_revision_id": "SRC-R01",
  "floor_source_ids": ["FS-01", "FS-02", "FS-03"],
  "geometry_status": "ABSENT",
  "scale_status": "NEEDS_CONFIRMATION",
  "height_status": "NEEDS_CONFIRMATION",
  "skill_id": "floorplan-to-dxf-pdf-glb@1.0.0",
  "model_profile_id": "qwen3-vl-4b-local-candidate",
  "privacy_policy_id": "local-model-bimface-opt-in",
  "requested_outputs": ["dxf", "pdf", "glb"]

```

这里的源 ID 必须在系统中已存在并完成上传校验。该请求允许创建任务，不允许直接跳过尺度/层高门禁。内容和 ID 是接口示例，不是声称已有用户建筑输入。

### 8.3 几何与对象身份

每个构件有稳定 `object_id`、`floor_id`、类别、参数/几何、来源区域、事实引用和可见性类别。对象 ID 不直接用数组下标，也不跨版本仅按包围盒猜身份。拆分/合并构件时记录 lineage。Approved IR 不被原地改写，修复形成新的候选 IR。

BIMFACE 的 elementId、GLB node/primitive、DXF entity handle、PDF page 与区域均与 object_id 建映射。文件 handle 和云端 ID 可以变，内部逻辑 ID 必须可追溯。一个墙对象对应多个网格/实体时映射为一对多，不能强求全格式数量逐一相等。

## 09｜同源导出、坐标与回读

### 9.1 三格式规则

| 成果 | 合同 | 独立验证 |
|---|---|---|
| DXF | 实际坐标乘 1000；毫米；$INSUNITS=4；按楼层和类别分层；可编辑文字/线/弧/块 | ezdxf 回读、audit、单位与尺寸、块变换、门洞和图层 |
| PDF | 矢量平面；默认 A3 横向；比例按可用图幅计算；中文嵌入子集；说明页不按比例 | 逐页渲染；检查文字、裁切、矢量统计及实际打印尺度 |
| GLB | 自包含；米；Y 向上；楼层和对象层级；完整装配 | 节点变换累计、资源内嵌、网格和洞口、实际浏览 |

所有导出使用同一 `geometry_version`，禁止让模型分别生成三份互不相干的成果。现有校验器是第一层检查，新增 cross_format_validator 才负责跨格式匹配。[U01]

### 9.2 变换链与联动依据

建筑坐标 B：米、右手、Z 向上。GLB 坐标 G：`G=(Bx,Bz,-By)`；逆变换 `B=(Gx,-Gz,Gy)`。只转换一次，避免坐标已转再在根节点重复转轴。

DXF 模型空间 D：`Dxy=1000×Bxy+sheet_offset_mm`；逆变换需去掉每层合图偏移后除 1000。PDF 点坐标：建筑米先乘 1000，再除比例分母并乘 `72/25.4`，叠加页内布局变换。二维合图与 PDF 页偏移永不写入三维建筑坐标。[U01]

BIMFACE 显示坐标 V 由适配器实测的 `T_B_to_V` 给出，不假定所有转换或外部构件路径都沿用相同单位/轴。保留转轴、单位倍率和模型全局偏移，至少用不共线 XY 控制点与独立高差点校验。

### 9.3 三格式同源不等于已经一致

回读时按对象类别和楼层比较轮廓、主要墙、门窗中心/宽度、洞口及标高；不能只看总包围盒或文件名 hash。GLB 要累计节点变换，DXF 要恢复块和排版偏移，PDF 要排除说明页。

建立同一模型的正交投影与输入图对照，检查漏墙/假墙及门窗；投影来自实际最终网格，不调用生图模型“美化验收图”。网页使用 IFC 派生模型时，还要比对 IFC/GLB/BuildingIR 的几何摘要和关键点，防止展示正确却下载错误。

## 10｜BIMFACE 接入方案

### 10.1 已核实的能力与不能推断的能力

BIMFACE 官方转换格式列表包括 DXF 和 IFC；官方 SDK 3.6.294 更新记录明确加入 glTF/GLB 的外部构件加载。**GLB 可以按外部构件路径展示；这不证明它已进入常规模型云转换管线，也不证明其子节点获得原生 BIM 属性/构件树/图模联动。** [B01][B02]

用户已有会员是接入条件之一，但账号实际的应用身份、SDK 初始化许可、API 配额、图模关联组件、离线/私有部署权益及 GLB 细粒度能力仍需账号 PoC。本文没有登录用户账号，未获得或记录任何密钥。

### 10.2 路线 A：直接展示最终文件，首期优先

二维：交付 DXF 通过 BIMFACE 官方上传与转换服务生成可浏览资源，WebApplicationDrawing 显示模型空间/可用布局。PDF.js 独立显示交付 PDF。[B01][B04][B08][B10]

三维：最终自包含 GLB 经本系统授权资源 URL，由 BIMFACE ExternalObjectManager 加载。它展示的是待交付 GLB 的实际几何；模型出处、尺寸、楼层、版本和风险说明来自本系统，而非假定 BIMFACE 自动解析 GLB extras。[B02]

必须验证：是否可在当前账号和所选 SDK 下合法初始化所需场景；GLB 单独加载是否需要有效宿主场景/模型；单位/轴向、透明材质、节点选择、楼层显隐、剖切、测量及销毁是否符合要求。官方示例展示加载，不足以证明这些高级项；不能用他人公开 viewToken 或无业务关系的模型作长期授权替代。

若 GLB 只作为一个外部整体对象，界面仍可保留基础浏览，但不得把对象级联动标为完成。缺少某功能时展示 `CAPABILITY_UNAVAILABLE`，交由路线 B 或自有适配能力补齐。

### 10.3 路线 B：原生 BIM 语义，按需启用

需要稳定原生构件树、属性检索和平台联动，而路线 A 实测不足时，从同一 BuildingIR 在 `_work/preview/` 生成内部 IFC。优先使用与 GLB 共用几何组件生成结构层级、IfcBuildingStorey、门窗开洞和设备代理，并附稳定业务 ID；不从 GLB 猜回 IFC，也不让大模型另造一套几何。[B01]

IFC → BIMFACE 云转换 → 原生构件浏览。IFC 的具体 schema/version、洞口解释、业务 ID 保留及属性解析通过格式 PoC 选择并锁定。若使用 IfcOpenShell，必须查其当前官方 API，并为每类对象建回读测试，不将“一份 IFC 能打开”当作工程 BIM 合格。[G03]

该 IFC **只供内部展示派生**，不进入用户建筑交付目录；策略项 `allow_internal_ifc_preview` 和 `cloud_publish_authorization` 通过评审后启用。路线 B 仍需提供最终 GLB 的独立核验视口，否则不能证明下载模型与网页一致。

### 10.4 二维图纸和多楼层浏览

先验证一份含三个楼层图块/布局的 DXF 在账号中能否正确转换、中文是否可见。若自动识别子图/布局不符合需求，由系统生成逐层内部 DXF 供网页使用，仍只交付一份多层合图 DXF。应用侧保存每层图块偏移，按钮可导航到对应范围；不假定平台自动拆图一定适用于本项目 DXF。[B08]

PDF.js 负责页切换、缩放、文字与图面阅读，PDF 的真实打印比例仍由回读和 100% 打印校验负责，而不是浏览器屏幕比例。[B10]

### 10.5 服务端调用顺序

以下为官方现有经典 API 路线；实际账号可能使用新文件管理/组件接口，必须先选定 api_profile，禁止混用不同 ID 体系。[B03–B07]

| 阶段 | 经典官方接口 | 本系统职责 |
|---|---|---|
| 应用凭证 | POST api.bimface.com/oauth2/token | 服务端以应用身份获取并缓存 Access Token |
| 上传 | PUT file.bimface.com/upload | 普通文件流 body，不按 multipart 表单套用 |
| 发起转换 | PUT api.bimface.com/translate | 登记幂等任务，保存 fileId 与输入 hash |
| 查询 | GET api.bimface.com/translate?fileId=… | 轮询终态；回调只作为加速提示 |
| 浏览凭证 | GET api.bimface.com/view/token?fileId=… | 鉴权后给浏览器 View Token，而不是 Access Token |

大整型资源 ID 在本系统数据库/JSON/前端统一按字符串保存。若平台响应为 JSON 数字，服务端用可保精度解析器接收后转换为字符串，再进入 JavaScript，避免直接 parse 后再 stringify 已丢失精度。

经典 API 与 BDFS Hub/Project/文件版本 API 不是相同命名空间。图模关联模块使用 projectId、moduleDataId 和可关联资源等数据，须在账户能力配置中明确绑定与映射，不能拿经典上传 fileId 直接冒充新文件版本 ID。[B07][B09]

### 10.6 鉴权、回调、资源与版本

AppKey/AppSecret 和 Access Token 只保存在服务端安全配置；不进入前端 bundle、URL、模型 prompt、日志或 Git。View Token 也作为敏感 bearer 凭证处理，只在内存持有，经本系统项目授权后发放，响应 no-store，过期重新申请。[B03][B05]

官方 View Token 文档说明有效期与持续访问有关，因此本系统登录过期不能被误认为能立即使已泄露的 View Token 失效。严格撤销需求须另测平台支持的撤销/数据失效能力；必要时由部署策略限制共享和长期资源公开。[B05]

Mac 开发优先轮询，不要求公网 callback。生产有 callback 时，不信任仅凭回调中的“成功”：使用一次性关联标识、幂等处理，并由后端再次查询官方终态；若平台提供可用签名机制再验签，不能假造它已提供。

GLB objectUrl 必须从浏览器可达，满足 HTTPS/CORS/凭证要求；服务端本地绝对路径或另一台机器的 localhost 都不是有效资源 URL。混合内容、浏览器私网访问限制和短期签名过期列入联调测试。只向获准服务发布本轮文件，不在日志暴露签名 URL。

每个云端发布记录绑定 deliverable_revision/hash；源图或 IR 变更后生成新发布记录，旧视图明确显示“历史版本”，不会悄悄替换。发布失败不删除本地成果，重试先查已有转换任务，避免重复计费。

## 11｜二维、三维与原图联动

原图点击 → source 坐标 → 建筑世界坐标 → 当前楼层对象空间索引 → 选中/定位三维对象。DXF 点击要先去掉图块排版偏移；PDF 点击须先识别图纸页和有效视口，不能将说明页坐标当建筑坐标。

三维点击 → BIMFACE elementId 或外部对象标识 → object_id 映射 → 对应楼层二维对象与原图证据框。存在一对多映射时选择对象集合并显示范围；不可映射时提示“不支持构件级映射”，不得选错一个最近对象冒充关联。

官方图模关联组件可作为进阶路径，但文档示例要求同项目、已转换二维资源，示例过滤 DWG。**不能据此承诺本项目 DXF＋GLB 外部对象自动支持该组件。** 首期应用侧联动先通过已知变换与映射实现；原生 Linkage2D3D 通过能力实测后接入。[B09]

BIMFACE 的 ViewerDrawing 文档区分 Model、Layout 和 viewportPosition；浏览器返回的 worldPosition 未必就是 CAD 模型空间位置。实现要依据本次视图类型正确取坐标并做标定，避免在 Layout 上量到了纸空间毫米。[B08]

## 12｜同一 Skill 的 Agent 执行机制

### 12.1 不是把文档当训练后的模型

SkillRunner 将原 SKILL.md 作为规则入口，依据当前阶段加载所需 references 和工具契约。被比较的大模型负责读图、整理事实、请求澄清、提出几何候选/修复建议及调用白名单工具；确定性工具执行校准、建模、导出和验证。

不会让一个强模型先完整识图，再把相同结果交给其他模型并称为“不同模型的识图对比”。共同预处理仅提供相同的非语义候选及原图，额外视觉助手必须登记为独立条件。

### 12.2 白名单工具与权限

| 工具组 | 动作 | 限制 |
|---|---|---|
| 读取 | 获取输入清单、按 ROI 读图、查事实、读 Skill 片段 | 只访问任务授权文件，不随图纸批注打开任意 URL |
| 提议 | 写 DetectionProposal、GeometryPatch、问题清单 | 只写候选区，严格 Schema，不修改批准字段 |
| 几何 | 校尺、拟合、跨层校验、生成网格 | 固定程序，参数检查，内存/超时限制 |
| 输出 | 导出三格式、回读、生成实际投影 | 仅任务工作区，白名单目录，不覆盖源文件 |
| 审批/发布 | 请求用户确认、获准后发布 BIMFACE | 模型不能自己批准、读取密钥或无授权上传 |

生产路径不直接执行模型输出的任意 Python、shell 或 CAD 脚本。为比较“让 Agent 写建模代码”的原始技能执行方式，可设独立研究轨：无网络沙箱、固定依赖、最小文件权限、CPU/内存/超时上限，并单列结果，不混入受控工具轨。

### 12.3 决策与过程记录

保存输入 prompt、工具调用参数、结果摘要、公开决策理由、错误与改动补丁，不要求模型输出私有思维链。固定 Skill 的内容 hash、按需加载片段及其顺序；运行器的任务进度和停止条件独立于模型自然语言“我已完成”。

模型最多提出预设次数的修复；修复不能新增输入不存在的房间或默认审批。达到预算后返回 `REVIEW_REQUIRED`，用户可在新版本继续，不无限重试直到挑到一张看起来成功的图。

## 13｜后端接口设计

**下列 `/api/p3/v1` 是本项目拟开发接口，不是已存在命令或 BIMFACE 官方接口。** 统一响应包含 request_id、status、data/error；创建任务使用幂等键和 base_revision。

| 方法与路径 | 用途 | 关键约束 |
|---|---|---|
| POST /projects/{id}/sources | 上传图片/文档 | MIME/大小/像素限制、内容 hash、原件不可覆盖 |
| POST /source-revisions | 确认楼层、裁切与文件集合 | 不变快照，区分原图和预处理图 |
| POST /calibrations | 写尺度、对应点和变换候选 | 记录证据/残差；确认另走审批接口 |
| POST /runs | 启动识图/重建 | model_profile、skill_hash、budget、input_mode |
| GET /runs/{id}/events | SSE/分页读取事件 | event_id 恢复游标；不能仅靠推送持久化 |
| POST /runs/{id}/cancel | 取消排队或发信号 | 被取消结果不能发布；已计费远端调用如实记录 |
| POST /geometry-revisions | 接收候选或修复补丁 | expected_revision 乐观并发，冲突返回 409 |
| POST /approvals | 用户批准参数/几何/云发布 | 真实认证主体和明确 scope，不接受模型自批 |
| POST /deliverable-revisions | 同源导出 | 必须引用批准或获准草模 IR，验证规则完整 |

| GET /objects/{id}/links | 2D/3D/源图映射 | 限定 project + revision |
| POST /experiments | 创建冻结模型实验 | 固定案例、模型配置、Skill/工具版本与预算 |
| GET /experiments/{id}/results | 对比明细与统计 | 失败、超时、NOT_RUN 分开，不能静默丢弃 |

错误码至少包括 NEEDS_INPUT、SCALE_CONFLICT、GEOMETRY_STALE、GEOMETRY_INVALID、MODEL_UNAVAILABLE、MODEL_FAILED、RESOURCE_EXCEEDED、EXPORT_INVALID、REVIEW_REQUIRED、BIMFACE_AUTH_FAILED、BIMFACE_CAPABILITY_UNAVAILABLE、PUBLISH_FAILED、VERSION_CONFLICT。

## 14｜状态机、历史与故障恢复

重建状态与展示状态分离。主状态：`INPUT_RECEIVED → INPUT_REVIEW → CALIBRATED → RECOGNIZING → IR_CANDIDATE → GEOMETRY_REVIEW → GEOMETRY_APPROVED → EXPORTING → FILES_VALIDATED → DELIVERED`。可在任意阶段进入 BLOCKED、FAILED、CANCELLED。草模审批使用单独 PROVISIONAL 标记，不伪装最终批准。

发布状态：`NOT_REQUESTED → AUTHORIZED → UPLOADING → CONVERTING/LOADING → READY`，另有 FAILED、EXPIRED、STALE。网页未就绪不影响“文件已生成”这个事实，但全网页功能发布门禁要求 READY。

每个动作以追加事件记录操作者、版本、关联 run、输入/输出 hash、公开摘要和 UTC 时间。旧数据不被覆写；撤销生成新版本指向之前快照。数据库事务先登记调用意图，再执行外部调用，成功/失败均写结果；崩溃后从持久检查点恢复。

相同幂等键只能对应同一请求体 hash；body 不同返回冲突。模型、导出、BIMFACE 转换分别有幂等域。用户取消不会声称已取消正在云端进行且无法撤回的转换，但会阻止结果自动发布。

## 15｜大模型候选与 Mac mini 16GB 策略

### 15.1 P3 测的是视觉理解与执行，不是生图美术风格

第一批以图文到结构化输出的视觉语言模型为主。SD/FLUX 一类生图模型不作为 P3 的几何真源；单张图生成自由网格也不替代可编辑墙、门窗、楼层和同源 CAD。可视化渲染从实际几何产生。

以下均为**待测试候选，不是本项目实测排名**。模型家族、视觉能力与身份由作者发布页核对；量化制品、运行器版本和在 16GB 上的实际表现需另行验收。[M01–M06]

| 层级与候选 | 作用 | 本地测试定位 |
|---|---|---|
| T0 人工金标准＋确定性工具 | 验证工具/导出器，给其他模型提供独立评分基准 | 不参与“大模型速度排名” |
| T1 Qwen/Qwen3-VL-4B-Instruct | 原图识读、坐标候选和工具调用 | 首批基线，优先测试兼容量化版本 [M01] |
| T1 Qwen/Qwen3.5-4B | 同尺寸新架构视觉语言候选 | 与上项固定输入对比；推理模式单独登记 [M02] |
| T1 google/gemma-3-4b-it | 不同模型家族的图文理解对照 | 先确认许可、量化和本地视觉调用可用 [M03] |
| T2 Qwen/Qwen3-VL-8B-Instruct | 同家族较大候选 | 16GB 条件试跑；视觉编码/KV额外内存不可忽略 [M04] |
| T2 openbmb/MiniCPM-V-4_5 | 另一个视觉模型家族 | 按本机已验证后端和权重许可试测，不保证内存 [M05] |
| T3 Qwen/Qwen3-VL-32B-Instruct | 更大本地硬件上的参考线 | 不作为 16GB 默认运行项；需批准资源 [M06] |

MLX-VLM 是针对 Mac/MLX 的候选视觉运行器，维护者提供多图、模型适配和量化相关能力；但“运行器列出家族”不等于某个量化文件及图片 JSON/tool-call 组合已通过本项目兼容测试。注册表须锁定实际模型 revision、processor、视觉投影器、权重 hash 和运行器版本。[M07]

### 15.2 兼容性探测先于性能排名

每个配置先执行：单图颜色/文字定位、同图两处构件区别、多图楼层区分、结构化 JSON、白名单工具请求、停止与最大输出、离线网络审计、超出预算终止。不能接收图片的纯文本运行器标 `INCOMPATIBLE`，不能用它处理自动生成的图纸摘要后假称独立识图。

模型名称中的参数量不等于精确权重总量，更不等于统一内存占用。内存包含语言和视觉权重、KV cache、图像 token、运行时、几何、浏览器和系统；不要用“4-bit 文件几 GB”保证整机能跑。

### 15.3 首批运行策略

先跑两个 Qwen 4B 候选与 Gemma 4B 跨家族对照；稳定后再试 8B。图纸逐层、局部块顺序处理；需要联合三层时优先结构化摘要加少量对齐证据图，不一次把所有高分辨率图放进长上下文。任何不同处理策略都作为新配置重新比较。

batch=1、并发=1、一个模型驻留。模型提案完成后落盘并卸载，再启动较重网格生成；浏览器只保留两个活跃三维视口。内存压力到预设阈值就取消任务或按已登记的小图配置重跑；不关闭系统保护、不静默转云模型、不把 OOM 排除出可靠性统计。

本地较大硬件和云 API 属不同评测组。用户当前的本地模型要求不因使用 BIMFACE 自动放宽；云 API 只有单独授权后才进入扩展试验，本文不设置自动 fallback。

## 16｜模型使用同一 Skill 的评测协议

### 16.1 三条评测轨，避免混淆责任

| 轨道 | 固定内容 | 变量与结果 |
|---|---|---|
| E1 识图轨 | 原图/裁切/参数、非语义候选、目标 Schema | 只换 VLM；输出构件识别、关系、证据与疑点；测识图本身 |
| E2 受控 Skill 轨，主排名 | 原 Skill、白名单工具、输入、几何引擎/导出器、预算 | 换负责读图和工具决策的大模型；测遵循、正确修复与产物 |
| E3 端到端产品轨 | E2 配置、网页版本、显示参数和账号通道 | 测三成果、网页、人工纠错、完成率与成本；平台问题分开归因 |

另设有/无 Skill 的消融实验，或允许模型写代码的研究轨，结果单独展示，不能混入 E2 公平排名。人工金标准 IR 只用于 T0 工具测试和评测，不提供给 E1/E2 模型，防止测试变成抄答案。

### 16.2 案例集和数据隔离

首个试点是一栋具有详细内部分隔的三层 L 形，至少含真实/明确给定尺寸、不同层高或层间关系、门窗、两类设备和卫生间。仅有外轮廓的旧样例不能承担 P3 识图验收；由程序合成图纸的案例明确标 SYNTHETIC。

初始建议 12 栋：4 栋开发、8 栋冻结评估；扩展阶段再至少形成 30 栋多样建筑。按建筑和版本族划分，不把一栋的一楼放训练/调参、二楼放留出。真实图需授权/脱敏；合成图纸从独立标注或不同工具制作，减少与本项目符号库完全一致的偏置。

难例包括：斜墙/弧边、内院/竖井、上下层轮廓不同、不同层高楼梯、密集机柜、模糊中文、尺寸冲突、净高/层高混用、分辨率变化和图片版本几何过期。错误输入预期正确结果可能是 BLOCKED/澄清，不是生成文件。

### 16.3 公平性和预算

冻结图像 bytes/hash、事实与批准、Skill 源包/加载片段、工具版本、系统模板、允许修复次数、每任务总调用/token/时间预算、量化和硬件。所有模型使用相同原图和可见证据；模型专属 processor 的视觉 token 差异如实记录。

建议首次候选生成 1 次，工具反馈修复最多 2 轮；每个模型×案例做 3 次独立完整试验。这里是工程初始实验预算，不是统计充分性保证。支持 seed 就记录实际 seed，不支持则写 null 并报告不可完全复现；temperature=0 也不保证跨硬件逐字节一致。

额外提示词优化用独立 `tuned` 排行，不能只给一款模型反复精修。保存所有首次失败、重试和被拒版本，primary_success_rate 分母包含失败/OOM/超时；平台停机同时给出含平台与模型本身两个口径。

### 16.4 指标与初始验收阈值

以下数值是**拟议试点门槛，必须在看留出集结果前评审冻结**，不是建筑规范、已有成绩或图片固有精度。

| 类别 | 主要指标 | 首个试点拟议门槛 |
|---|---|---|
| 输入与授权 | 不凭空补尺度/层高；未经授权设计改动 | 所有关键缺失/冲突正确阻断；未授权改动 0 |
| 轮廓与结构 | IoU、中心线距离、漏/假墙 | 清晰合成例轮廓 IoU≥0.98；关键墙无缺失，人工复核 |
| 门窗与楼梯 | 检出 F1、宿主准确率、中心/宽度误差 | 关键宿主与楼梯连接全部正确；不可只用平均分掩盖漏楼梯 |
| 数值导出 | IR↔DXF↔GLB 关键几何差 | 默认≤1mm 数值容差；独立记录源图重建不确定度 |
| PDF | 中文、页裁切、矢量与打印比例 | 无缺字/裁切；比例量测拟议偏差≤0.5% |
| 网页 | 实际文件、单位、楼层、映射和版本 | 关键对象/标定点正确；无跨项目权限泄漏 |
| 过程 | 事件、失败、版本与审批证据 | 记录完整率100%，回滚和恢复通过 |
| 资源 | 冷/热启动、耗时分位、峰值内存、OOM | 按实测预算报告；不预填秒数或内存通过 |

识别 F1 的匹配需同时考虑类别、平面位置与宿主，不只按房名。几何误差用人工标注的有效精度区间解释；墙中心线可报告双向距离/P95，开洞报告中心偏差和宽度误差，楼梯报告连接终态与净空检查覆盖。

对图片抽取精度较差的候选，最终人工修正后可能仍达产品标准，但必须分别报告 raw、auto_repaired、human_corrected，记录修正次数和分钟数。

### 16.5 排名与选择

先做硬门禁，未过者只显示失败原因和局部指标，不与通过者计算美观综合分。通过后按几何保真、Skill 遵循、稳定性、人工修正量、资源成本和网页质量建立 Pareto 比较；若需要综合分，权重预先冻结，不事后调整让偏好的模型获胜。

模型质量主要依据 BuildingIR/实际文件，而不是 BIMFACE 的漂亮渲染。所有候选使用同一灯光、材质、相机和版本；平台转换失败单独标注。至少两名评审对关键难例盲评，分歧留记录。小样本显示原始分数与范围，不凭一栋成功宣布普遍最佳。

每次试验还保存 model_id、weight_revision/hash、quantization、processor、skill/tool commit、case/split、原图与 facts hash、预算、raw proposal、补丁、文件 hash、检查状态、耗时、token、内存和人工审批。`NOT_RUN` 不能计为 PASS；模型自评分不作最终裁判。

## 17｜测试体系和发布门禁

### 17.1 测试层次

单元测试覆盖事实依赖、尺度/单位、变换逆映射、轮廓孔洞、墙连接、洞口、楼梯累计高差、审批和幂等。合同测试覆盖 IMAGE_ONLY、匹配侧车、STALE 重新识图、错误 ID 和 Schema 版本迁移。工具集成测试从确定性 fixture 同源导出，回读三文件。

视觉与浏览器测试以 Playwright 等可控浏览器运行上传、校尺、SSE恢复、两视口联动、Token过期和下载；保存实际文件截图。模型测试在指定本地硬件运行，不能用 CI mock 模型称成功。BIMFACE 测试需要单独获准的账号测试空间，禁止 CI 自动上传用户图纸。

### 17.2 必须包含的负例

| 负例 | 预期行为 |
|---|---|
| 图上尺寸矛盾、没有可靠尺度或层高 | 阻断关键建模，展示待确认参数 |
| 一楼与二楼楼梯错位 | 不自行挪动；生成冲突和证据 |
| DXF 仅改单位头但几何未乘1000 | 回读尺度校验失败 |
| GLB 已转轴再根节点二次旋转 | 关键标定点/楼层高差检查失败 |
| 二维布局合图偏移写进三维 | 楼层对齐失败 |
| 门弧存在但墙未开洞 | 开洞检查失败，不能以图像相似通过 |
| P2 改图但侧车仍是旧版 | 不消费旧几何；创建新 IMAGE_ONLY 识读 |
| 给 BIMFACE 前端 AppSecret | 安全扫描失败，禁止上线 |
| 云端转换晚到、重复回调、取消后完成 | 幂等、版本检查；不自动发布旧结果 |
| 本地模型未加载/工具 mock 成功 | 模型实验仍 NOT_RUN 或失败，不能记录真实推理完成 |

### 17.3 里程碑门禁

G0：原 Skill 完整导入、24项原回归通过、BIMFACE 能力 PoC 路线定案。G1：人工确认 IR → 三格式 → 真实网页可看，证明工具链。G2：一款本地 VLM 从详细图片产生可复核 IR，单栋三层闭环。G3：至少三候选模型按冻结协议完成对比，失败全部归档。G4：跨 P2 版本、恢复/权限和交付审批通过，才接入总 Agent。

每门禁区分 SOURCE_VERIFIED、TOOL_TESTED、MODEL_TESTED、VIEWER_TESTED、USER_ACCEPTED；前一状态不自动意味着后一状态。施工/报审合规不在本发布状态内。

## 18｜Mac mini 16GB 部署与可观测性

不假定 Mac 的芯片型号与系统版本已知，首次安装记录型号、macOS、统一内存、可用磁盘、浏览器、Python/Node 和模型后端。优先原生 Apple Silicon 的独立环境，不把 NVIDIA/CUDA 命令照搬到 Mac；不与 DocRes/IOPaint 环境混用。

服务建议分为前端、P3 API、持久任务 worker、本地 VLM worker。模型 worker 可按需启动并在阶段结束退出；几何和文件校验环境单独锁定依赖。模型资源不进入仓库。BIMFACE 发布由后端可选网络模块执行，本地识图/几何 worker 默认不联网。

指标至少含：任务队列等待、模型加载/首响应/生成时长、视觉 token、导出及转换耗时、进程 RSS、后端设备分配统计、系统内存压力、浏览器渲染耗时、帧率及上下文数。Apple 统一内存下不同统计可能重叠，不能把 RSS 和 Metal 占用简单相加后称精确峰值。

性能试验分冷启动与热启动；记录电源模式、同机其他进程与显示候选数量。长任务有取消和超时，错误页面显示可恢复阶段。首期不承诺“每栋几秒”；用真实案例实测后设 SLO。

## 19｜隐私、安全和费用边界

已购买 BIMFACE 不代表所有原始发电厂图纸都获准上传。本地模型推理与 BIMFACE 云展示是两种不同的数据流：前者默认本机；后者按项目和版本取得发布授权。对敏感数据先用合成建筑做 PoC，真实图纸按组织要求脱敏或选择获准部署方式。

上传最少必要内容。DXF/IFC 转换通常涉及远端存储与处理；GLB 外部资源至少被浏览器和资源服务读取，SDK 也可能需在线授权/资源，不能称“整个应用完全离线”。离线数据包或私有部署权益须单独核验。[B01–B07]

接口权限按用户、项目和 revision 检查；防止凭猜 fileId 获得他人 viewToken。URL导入限协议与域，阻断任意内网/本地文件访问；上传限制像素、解压比、页数和大小。图片、PDF批注中的指令只视为数据，不执行代码或变更交付范围。

密钥不出后端；BIMFACE Token/签名URL打码；CSRF/CORS/会话过期和日志权限要测试。基准集不能混入未经批准的生产图纸。删除本地数据、云端资源及模型缓存分别明确授权与保留策略，审计 hash 链不被描述为不可被管理员篡改。

费用记录模型运行资源、BIMFACE 转换/存储/流量等实际可取指标；具体价格/会员额度通过账号核验，不预设无限调用。取消和重试不自动保证平台不计费，界面应显示已发生的外部动作。

## 22｜首个试点的具体验收脚本

### 22.1 数据准备

选一栋详细设计完成的三层 L 形；每层有明确墙门窗、楼梯和设施，而不是只拿旧外轮廓。由用户提供可靠尺度、层高含义及跨层定位，或者使用明确标注 SYNTHETIC 的评测建筑。原 Skill 的 H 形50×30米、4/3/3米未决案例只用于“应当阻断”的回归，不默默转为已确认 L 形参数。[U01]

### 22.2 操作顺序

第一次只验证工具：用人工确认的 BuildingIR 生成三格式，校验真实门窗和楼板洞口，在网页看 DXF/PDF/GLB。第二次隐藏金标准 IR，只把相同详细图片与可公开事实给一款本地 VLM，按 Skill 执行并比较误差。第三次对其余模型重复完全相同的试验预算。

每次记录：三层原图hash、参数与批准、模型/Skill/工具版本、未修复识别结果、工具补丁、最终IR、三成果hash、回读/网页证据和人工修正分钟数。结果不佳不能换一张更简单的图后沿用同一个试验ID。

### 22.3 第一阶段完成定义

用户能独立上传详细图片；系统能阻断未知尺度和楼梯冲突；至少一款本地模型完成完整候选重建；网页二维与三维呈现真实成果；三个下载文件可编辑/可读/自包含且一致；低置信度与假设可追溯；失败与恢复真实可用。只有以上完成才记 P3 单案例 MVP，不以24项旧检查器测试或三份空文件替代。

## 23｜主要风险与需要评审的事项

| 风险或待确认 | 文档默认策略 |
|---|---|
| 原图详细但缺乏层高/窗高/板厚 | 证据台账＋按需询问，不自动填成事实 |
| 原 Skill 仅检查器，重建工作量被低估 | 几何与导出器单列任务，先人工IR验证 |
| GLB外部构件只支持整体选择 | PoC后启用IFC语义路线或明确受限功能 |
| DXF布局/中文/原生图模关联不兼容 | 应用侧定位、内部逐层DXF；不暗改交付格式 |
| 网页云展示与本地隐私冲突 | 单独发布授权；先合成数据；敏感项目另评 |
| 模型输出看似正确但漏墙/假门 | 原始候选、硬门禁、真实投影和人工复核 |
| 16GB同时推理与多视口内存压力 | 串行分阶段、卸载、两活动视口、记录OOM |
| 不同模型不同工具预算造成偏差 | 固定E2条件，调参/特殊助手另列实验 |
| 过期几何/云缓存展示成最新版 | 不可变revision、hash绑定、发布状态单独管理 |
| 未决/近似模型被当成施工图 | PROVISIONAL和范围说明；不生成施工批准状态 |

进入实现前，产品负责人只需确认仍未知的四类事项：首个详细案例的使用权限与缺失参数；BIMFACE应用/API权益及允许上传范围；GLB路线不足时是否批准内部IFC派生；评测数据规模和初始门槛。不要在聊天里索要账号密码或明文Secret，配置在用户自己的运行环境。
