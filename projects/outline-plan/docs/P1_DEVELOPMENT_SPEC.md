# P1 开发准备：SVG编辑、尺寸轮廓、参数驱动布置与同源模型实验

版本：0.2.0-design｜日期：2026-09-11｜对应总控：CONTROL.md｜状态：DESIGN_REVIEW

本轮只交付可实施设计、默认参数样例、实验配置和准备资料检查；不把文档、配置测试或旧L形基线当成新前后端已实现。不生成新的H形方案，不采用此前生图里的50×30米、17/16/17分段作为用户输入。P2区域编辑、P3导出与其已登记阻塞均不在本次改动范围。

## 1. 产品目标与验收主线

用户绘制或接口导入同一个SVG，确认单位和尺寸，保存为工程风格轮廓图；填写楼层、工位、机柜、机房及配套参数；选择一组或多组模型配置；得到逐层平面图片、设计决策记录、参数实现对照和可供P2/P3使用的版本数据。

核心原则：SVG/几何负责边界，参数负责数量，布局求解负责约束，模型负责候选建议或视觉表现。工程标注和实际数量不让生图模型自行决定。保留“无生图模型”的确定性基线，分开评价布局与画面质量。

默认用发电厂辅助控制/办公用房模板，不代表主发电机组工艺布置。首版重点覆盖1~3层矩形/L形正交轮廓；其他合法形状可以导入预览，但未实现的布局能力必须明确UNSUPPORTED，不能换成矩形。后续再扩展曲线、孔洞、复杂凹多边形与更多楼层。

## 2. 前端信息架构

主路径：①轮廓工作台 → ②功能参数 → ③模型实验 → ④生成过程 → ⑤结果对比。

顶栏始终显示项目/建筑、草稿或快照版本、尺度状态、未保存修改、任务队列。侧边保留步骤导航，模型配置与历史实验是独立页。默认三栏：左工具/楼层，中画布，右属性或参数；底部状态栏显示坐标、实际单位、捕捉精度和校验问题。

### 2.1 轮廓工作台

工具：选择、折线闭合、矩形、顶点移动/增删、内洞、长度标注、入口标记、楼层复制、撤销/重做。首版正交绘图；按键临时取消捕捉。曲线工具不在首版承诺中，导入曲线先保留并提示能力限制。

画布：SVG矢量主视图＋独立标尺/标注层。上/左标尺显示米，随缩放改变刻度密度而非改变实际几何；网格与捕捉步长分开配置。光标显示世界坐标和临时边长，闭合前显示终点至起点距离。平移、缩放、适合窗口不能修改顶点。所有楼层使用同一世界原点；切层可显示半透明下层参考与固定核心。

选中一条边：右栏显示端点坐标、长度、方向、锁定状态；输入长度时明确“固定起点/固定终点/保持中心”。修改是约束操作，不是覆盖尺寸文字。首版不做通用CAD约束求解：保持正交与闭合需要传播到哪些顶点，先预览变更；遇到锁定约束冲突则拒绝，禁止偷偷移动其他楼层。

导入：支持上传SVG、粘贴SVG文本、API导入记录。多闭合路径时让用户选择外壳/孔洞；不能把边框、尺寸箭头、文字外框算进建筑。保留原SVG，服务器仅将审查过的形状转换成可编辑几何，预览不得直接插入不可信SVG的innerHTML。

SVG的viewBox、px、width="500mm"属于图形坐标/显示尺寸，不能自动推导真实建筑宽度。尺度校准可选：绘图时世界单位；指定一条边真实长度；确认已知总宽/总高；可信附带尺度元数据。单长度只在相似变换成立时够用。总长总宽与原比例冲突要显示冲突，不进行静默非等比拉伸。

保存行为分两级：自动保存草稿不启动模型；点击“保存并冻结轮廓”经校验后创建不可变OutlineRevision，并生成以下同源文件：

| 文件 | 用途 |
|---|---|
| source.svg | 原输入，只读留存 |
| canonical.svg + geometry.json | 规范化轮廓与世界坐标，不恢复不存在的原始精度 |
| outline_engineering.svg/.png | 白底、黑色轮廓、细尺寸线、总尺寸/分段/凹口尺寸、单位、版本和假设标识 |
| outline_clean.png / mask.png / edges.png | 模型用无文字轮廓、内外掩膜和边缘图 |
| transform.json + validation.json | 像素/世界变换、来源、尺度与几何检查 |

工程图中的尺寸由几何计算，不允许输入文本覆盖真实长度。图名、尺寸、公差说明均由程序排版。PNG不是实体打印比例保证；没有已知北向不放真北箭头。数值精度不等于源图精度。

失败状态：未闭合/自交/尺度未确认/多路径未分类/不支持的SVG元素/尺寸冲突。画布高亮对应对象，提供修正入口；“保存草稿”可用，“冻结并生成”不可用。

### 2.2 功能参数页

分区：建筑基本信息、总量要求、机柜分组、楼层分配表、设施尺寸与净距、空间关系、生成样式。支持载入模板、恢复某个字段默认值、保存个人模板、导入导出参数JSON、查看版本差异。参数“默认/用户修改/推导/待确认”标签必须可见。

本轮给出的是可修改的演示默认值，不是工程标准，也不是用户确认的建筑尺寸。总量口径为整栋，不按每层复制。

| 参数 | 演示默认值/口径 |
|---|---|
| 层数 | 3层；变更层数时先展示分配重算，不自动丢弃有数据楼层 |
| 办公工位 | 整栋24个，F01/F02/F03=4/12/8；不含会议座位与控制台席位 |
| 机柜 | 整栋24台，3个机房，每房8台；F01两房16台，F02一房8台，F03为0 |
| 办公室 | 1/2/2间，共5间；工位必须分配到具体办公室 |
| 会议室 | 0/1/1间，各8座；与工位独立计数 |
| 控制室 | F02一间，6个控制台席位；不是额外6个办公工位 |
| 卫生间 | 每层一组男/女卫，共6间；实际洁具数/无障碍要求待输入或单独配置 |
| 楼梯 | 演示2处固定核心；数量并非疏散合规结论 |
| 层高 | 演示4/3/3米，默认值需确认；P1二维草案可保留待决，不据此声称楼梯三维已验算 |
| 构造/净距 | 外墙0.30、内墙0.20、走廊2.40米；机柜0.60×1.20、前后预留1.20/1.00米；工位桌面1.40×0.70米，均为概念测试参数 |
| 实际外轮廓尺寸 | 不提供默认数值，必须来自当前SVG与尺度确认 |

机柜分组表字段：room_id、楼层、机柜数、设备类型、单柜外包、排数/朝向、前后维护区、相邻/隔离偏好。数量可以均分或自定义；24柜/3房可建议8+8+8，但25柜时必须展示9+8+8等建议并等待保存，不向下取整漏柜。容量不足也不能删柜完成图面。

楼层表同时显示“要求/已分配/剩余”。强制验证各层工位之和=整栋工位、各机房柜数之和=整栋机柜、实际机房条目数=要求数。0必须代表不需要，null代表未确定；负数、小数数量、溢出和重复ID报错。数量约束支持exact/at_least，首版默认exact；偏好不能覆盖硬数量。

单元面积不足时显示哪些功能/净距冲突，提出降低数量、改变分配或调整轮廓的选项；不得自动执行。会议席位和控制台席位不能混入办公工位达成率，更不能把总席位当消防设计人数。

### 2.3 模型实验页

模式分为：单方案、规划模型比较、图面模型比较、完整流水线比较。下拉分别选择planner、solver配置、renderer、reviewer。每项显示本地发现/权重缺失/接口未适配/未实测/内存未测；未适配项禁用，不能让“模型已下载”显示成“可以生成”。

先冻结SVG规范化版本、尺度、功能参数及图像预处理配置，显示输入摘要。每次编辑SVG或参数形成新快照，不修改正在排队的实验。选择模型组合、候选数和种子后预估任务数量，不虚构预计耗时；可取消未开始任务。

首轮提供T0确定性、Qwen3-4B规划、Qwen3-8B规划、SD1.5+Canny、SDXL+Canny和可选FLUX.2 klein编辑配置；运行适配和实测另列任务。详情见MODELS_PREPARATION.md。

### 2.4 过程页

展示公开可核对的“设计决策与执行过程”，不展示或编造模型隐藏思维链。左侧阶段时间线，中间中间成果，右侧使用参数/检查结果/待确认项。

事件：outline.validated → program.allocated → core.proposed → layout.solved/needs_revision → layout.validated → render.started/progress/completed → postprocess.completed → review.required。

每条记录含事件序号、阶段、输入引用、决策摘要、约束依据、被比较方案、实际检查数值、结果文件、耗时和警告。例如“24柜按用户保存的分组分为3房×8柜”；“候选B使一间机房少2柜，未达到exact=24，已拒绝”。示例只说明格式，不伪装实时结果。

阶段百分比来自已知任务/采样进度；未知耗时用等待状态，不播放假的思考打字动画。刷新页面通过持久事件序号续读；请求取消显示取消中/已取消并记录，不能直接宣称模型停止。

### 2.5 结果与对比页

楼层页签＋候选列，联动缩放和世界坐标；支持查看轮廓输入、无字布局、原始模型图、最终标注图、几何叠加。维持同尺度，有不同画布时显示配准变换而不是拉伸。

每候选显示要求数量/几何实配数量/图像目视待确认数量、净空间面积、几何有效性、原图轮廓漂移、耗时、硬件、失败原因。生图画出多余桌子时不能拿JSON的24冒充像素内恰好24；正式参数模式由程序放置带ID的设备符号，原图另存供比较。

选择方案默认以整栋同一个candidate为单位，不随意拼接不同模型的楼层。混选楼层须创建新候选并重新校验跨层核心、总量和版本。用户接受后生成PlanRevision交给P2；修改后必须重新确认，不自动进入P3。

## 3. 后端组件及责任

建议栈：React + TypeScript + 原生SVG/标尺层；FastAPI + Pydantic；SQLite(WAL)＋本地内容寻址文件；Shapely平面几何＋OR-Tools CP-SAT离散候选选择；审查后的SVG由resvg渲染；Ollama规划/视觉接口、ComfyUI图面接口。MFLUX为后续FLUX适配选项。技术依据见模型准备文档参考链接。这是选型建议，不表示依赖已安装。

不把长时推理放在HTTP请求或无持久化BackgroundTasks中。API负责校验/入库/队列；独立worker按租约取任务，GPU/统一内存资源锁串行加载。前端只连P1 API，不直连Ollama/ComfyUI。

模块：svg_ingest、geometry_normalizer、dimension_renderer、program_allocator、layout_planner、layout_solver、layout_validator、model_adapters、run_scheduler、decision_events、artifact_store、comparison_service。未来frontend/backend可独立构建；P1不import P2/P3内部代码。

### S0 SVG安全与规范化

限大小/节点数/坐标范围/解析时间，拒绝DTD/实体、脚本、事件属性、foreignObject、外链、网络字体和非许可资源；禁用任意服务器URL导入。首版支持rect/polygon/封闭path的M/L/H/V/Z和可验证的group/transform；use先本地展开或报不支持，文本/图片不能当轮廓。

保留原SVG与规范化几何各自hash。展开矩阵后确定外环/孔洞和fill-rule，坐标转换只做一次；拓扑错误先报错，不盲用buffer(0)修复后声称原图正确。弧线后续采用带误差上限的离散近似并保留源曲线。

### S1 尺度与工程图

统一建筑XY单位为米，显示SVG的Y向下与世界Y方向用显式变换表示。数值计算保存有效精度，显示位数独立。长度由端点距离、分段由实际边生成；支持水平/垂直/斜边尺寸。排尺寸时做层级避让，保证不会压到轮廓或相互遮挡。

同一几何产生带标注的人工输入图和无标注的模型图，二者共用变换。不要把尺寸箭头/文字送入Canny当墙体；VLM可看尺寸图，数值仍以结构化尺度证据为准。保存图的画布/比例变化不改变物理尺寸。

### S2 功能程序和约束

先用确定性校验整理用户明确数量与分配，LLM仅提出房间关系、功能分层及可选布局策略，输出严格JSON。用户数量、锁定几何和批准信息不让模型覆盖；JSON Schema合格不等于可实现。

建立ProgramSpec：稳定房间/设施ID、面积范围、精确数量、允许楼层、朝向/相邻/隔离、固定核心、入口。先估计需求面积区间与可用面积；该预检只可发现明显不足，不能证明空间可装下。参数假设与真实测量分开存。

### S3 跨层核心、交通与候选生成

先在各层真实可用边界中找共同核心候选，核验楼梯/竖井连通的平面位置；用户给per_floor时不统一外壳。方案级二维只检查井道/平台占位，真实台阶净空等留待P3和专业校验。

每层：外壳扣除墙带/孔洞/固定核心，提出连续走廊带，再枚举房间槽位和机柜/工位阵列。外包面积、墙体面积、净房间面积、交通及未分配面积分账；不能重叠计算覆盖率。凸/凹形完全包含用多边形covers核验，不能只检查四角在边界内。

初版以正交矩形/L形的候选槽位＋整数网格解决房间摆放；例如0.10米搜索步长是可改测试配置，不是建筑精度。完整设施外包与所需服务净区都要落在房间内；共享维护通道以明确规则处理，不能机械叠加或忽略。

### S4 求解与检查

CP-SAT选择候选槽位，约束每个必需房间被分配、各房/各层容量总量满足、非重叠、核心固定和走廊/门关联；规划模型可提供软偏好，不直接主导最终坐标。优化项可含交通长度、相邻满足度、房间紧凑性/采光偏好和未用面积；权重预先版本化。

CP-SAT在整数离散模型上求解。OPTIMAL仅指该候选模型，FEASIBLE不是最优，UNKNOWN/超时不是不可行；INFEASIBLE也只证明当前约束/候选集无解，不能推断任意建筑布局不可能。首次可用60秒预算，试验前固定；不满足则允许明确调整候选范围后新建attempt。

Shapely做最终连续几何复核；再做门宿主、净通道连通图、稳定设备ID和容量校验。模型候选最多允许明确预算内的结构化修复，不能无限抽卡。失败保存最小已知冲突及证据，不擅自减工位/删机柜。

### S5 逐层图面生成

每层生成wall/door/core/furniture等确定性图层与无字guide，配套mask/edges。ComfyUI逐层img2img＋匹配Canny；FLUX参考图编辑使用自己的适配器和参数，不能把SD1.5的ControlNet或CFG照搬。

正式可继续编辑模式：权威几何、中文、尺寸和精确数量符号由程序生成；AI只作用于允许表现区。完整AI图保留为raw并独立审查；任何保护层覆盖都不计入raw保真成绩。可选“纯图像端到端探索”必须单独归组并标IMAGE_ONLY，未经识图重建和复核不得给P2/P3当匹配几何。

### S6 版本、持久化、输出

数据实体：OutlineRevision、ProgramRevision、InputSnapshot、Experiment、Candidate、FloorJob、Artifact、DecisionEvent、ReviewEvent。每个步骤记录输入hash和输出hash，写盘采用临时文件＋原子重命名；数据库事务提交引用。无结果即失败，不能写成功占位图。

进程中断后用租约/心跳回收未结束任务，先查provider prompt_id再决定恢复，避免超时后重复入队。SQLite下多进程claim需事务，默认单worker；Ollama/图面模型切换释放资源。不能用ComfyUI全局interrupt误取消别人的任务；无任务级取消能力时等待受控任务结束并记录限制。

P1输出每层PNG、三层组合PNG、结构化布局、决策记录、参数对照和PlanRevision；尺寸/图形/业务参数/渲染任意版本变化均使对应下游成果过期。跨项目PlanRevision新增字段先走GOV-01合同评审，本轮不静默改变现行0.1.0合同。

## 4. 接口设计草案（尚未实现）

统一前缀 /api/p1/v1，错误返回code/message/field_errors/artifact_refs。轮廓草稿保存与正式冻结分离。控制端本机访问但仍校验Origin/Host、会话令牌和请求体，CORS不开放任意站点。

| 方法/路径 | 行为 |
|---|---|
| POST /outlines/import | SVG文本或上传＋尺度证据，返回草稿id、警告和预览；不接受任意URL下载 |
| PATCH /outlines/{id}/draft | 几何操作或参数修改，If-Match防止覆盖并发版本 |
| POST /outlines/{id}/freeze | 校验并冻结，返回outline_revision、工程/无字图artifact引用 |
| POST /programs | 保存功能参数，返回总量/分配差异和参数版本 |
| POST /snapshots | 绑定轮廓/参数/预处理版本并计算输入指纹 |
| GET /models | 实际已发现模型、适配能力及健康状态；不得只返回静态安装成功 |
| POST /experiments | 输入快照＋组合/模式/种子/预算；202返回experiment_id |
| GET /experiments/{id} | 楼层/候选/运行状态，不用HTTP成功代表方案成功 |
| GET /experiments/{id}/events | SSE含递增id；Last-Event-ID支持续读 |
| POST /experiments/{id}/cancel | 请求取消，保留原始事件 |
| GET /experiments/{id}/comparison | 指标、假设、同源摘要及raw/final引用 |
| POST /candidates/{id}/accept | 用户确认具体revision/hash，生成对外PlanRevision；不自动进入P3 |
| GET /artifacts/{id} | 授权读取受控文件；禁止客户端指定服务器路径 |

## 5. 同一个SVG的多模型实验

“同源”锁定source_sha、normalized_geometry_sha、scale_revision、program_sha、preprocessor_sha、canvas_transform。SVG字节不同但几何等价的合并不在首版保证中；输入快照ID是复现实验的单位。

A规划对比：Qwen3-4B与Qwen3-8B读取同一结构化输入，固定solver版本/候选预算，renderer=deterministic。比较约束/数量满足、连续几何、人工修改量与耗时。

B图面对比：固定同一个已通过布局layout_sha，分别用SD1.5+Canny、SDXL+Canny、FLUX.2 klein参考编辑。不同原生分辨率/后端分别记录，在共同世界坐标评估，不人为要求所有家族相同步数。

C整链路对比：同一个SVG快照，允许模型组合各自规划/表现，比较整栋完整候选。结果不能解释成仅图面模型的差异。geometry_image入口和纯image入口亦需分组。

例：3个图面配置×3个种子×3层=27个逐层任务，但只有先通过兼容性检查的配置才实际入队；T0无采样种子，不为了凑数重复算。遇到OOM/失败不能用上一张成功图填空。首次资源预检不适配标NOT_RUN/INCOMPATIBLE，不算模型质量失败。

指标：硬约束通过率、精确数量达成率、原始图外壳/假墙漂移、最终图保真、可读性、延迟/冷启动/内存/swap、人工修正分钟和失败类型。所有已执行失败入分母；未运行不入分母；只有3样本时呈现样本数据不夸大p95统计。数值阈值在试验前冻结，指标为空必须显示未检查，不让模型自评分直接决定冠军。
